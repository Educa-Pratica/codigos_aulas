1.LLMs vs. SLMs

A revolução da IA começou com modelos gigantes — mas o foco atual para devs e uso local está na eficiência.

LLM
🐘 Large Language Model
  • Dezenas de bilhões a trilhões de parâmetros
  • Ex: GPT-4, Claude 3
  • Exigem clusters de GPUs em data centers
SLM
🐝 Small Language Model
  • Entre 1B e 14B parâmetros
  • Ex: Llama 3 8B, Phi-3, Mistral
  • Desempenho próximo aos LLMs, cabendo em PCs e celulares

1.1Destilação: como nascem os SLMs

1

Um LLM gigante (o Professor, ex: GPT-4) gera milhões de respostas, raciocínios passo a passo e explicações perfeitas.

➜
2

Um modelo bem menor (o Aluno) é treinado com esses dados para imitar a lógica e o estilo do professor.

➜
3

O modelo pequeno herda a capacidade de raciocínio do gigante — sem precisar da mesma quantidade de parâmetros.

💡 É assim que surgem SLMs poderosos: qualidade de modelo grande, tamanho de modelo pequeno.

2.Como consumir LLMs ou SLMs?

☁️ Provedor Externo
Infra terceirizada
  • Toda a infraestrutura de inferência é do provedor
  • Pontos negativos: custo e segurança
  • Alguns provedores podem usar seus dados para fine-tuning
💻 Local
Você no controle
  • Controle de 100% do fluxo: infra e modelo
  • Mais segurança, custos menores (nem sempre!)
  • Maior complexidade de setup

2.1O problema para rodar IA local

O maior gargalo para rodar localmente não é o processador — é a memória (RAM/VRAM).

  • Problema: cada parâmetro usa 16 bits (FP16) → um modelo de 8B precisa de ~16 GB só para carregar.
  • Solução (Quantização): reduzir a precisão matemática dos pesos (16 → 8, 4 ou até 2 bits).
  • Resultado: 8B em 4 bits → ~4–5 GB de RAM. Perda de qualidade marginal, ganho de acessibilidade massivo.

🥧 Analogia: quantização é como arredondar o número π — 3,14159 ocupa mais memória que 3,1. Você perde precisão, mas na prática o resultado quase não muda.

FP16 (padrão)
8B params → ~16 GB VRAM
4-bit quantizado
~4–5 GB RAM

2.2Tipos de Quantização

PTQ
Post-Training Quantization
  • Modelo treinado em alta precisão (16 bits)
  • Compressão aplicada depois de pronto
  • ✅ Abordagem mais comum, rápida e barata
  • ⚠️ Leve perda na qualidade das respostas
QAT
Quantization-Aware Training
  • Treino/fine-tuning simulando a quantização
  • Modelo "aprende" a compensar a perda matemática
  • ✅ Modelos muito mais precisos
  • ⚠️ Custo computacional altíssimo para criar

2.3AWQ vs. GPTQ vs. K-Quant

Todas são técnicas de PTQ, mas com estratégias e objetivos diferentes:

GPTQ
  • Quantiza os pesos e usa informações de 2ª ordem (matriz Hessiana) para minimizar o erro, ajustando os pesos vizinhos para compensar
  • Uma das primeiras abordagens amplamente usadas para quantizar LLMs em 4 bits
AWQ
  • Nem todo parâmetro tem a mesma importância: monitora ativações reais e descobre que ~1% dos pesos são críticos
  • Protege esses 1% em alta precisão e quantiza agressivamente os 99%
  • ✅ Geralmente supera GPTQ em qualidade e velocidade
K-Quant
  • Divide os tensores em blocos (block-wise): partes cruciais recebem mais precisão (6 bits), as demais menos (3–4 bits)
  • Eficiente em CPU, também usável em GPU
  • Gera arquivos GGUF para o llama.cpp

4.Motores de Inferência

llama.cpp
🦙 CPU / ARM

O motor por excelência para GGUF. Escrito em C++, extrai o máximo de CPUs e chips ARM (Apple M-series). Sem GPU potente? Esta é a ferramenta.

vLLM
🚀 GPU / Produção

Focado em Safetensors (AWQ/GPTQ) e GPUs dedicadas. Usa PagedAttention para gerenciar VRAM. Ideal para servir dezenas de usuários (alto throughput).

Ollama
🐳 User-friendly

Interface "estilo Docker" para IA local. Por baixo dos panos usa o llama.cpp. Roda um modelo com um simples ollama run llama3.

5.Prática: instalando o llama.cpp

1️⃣ Instalar (Windows / PowerShell)

# https://llama.app/
irm https://llama.app/install.ps1 | iex

2️⃣ Baixar e servir um modelo (exemplo Hugging Face)

llama serve -hf ggml-org/gemma-4-E2B-it-GGUF

➜ Sobe uma API compatível com OpenAI em http://127.0.0.1:8080/v1

3️⃣ Chamada via API + LangChain

from langchain.chat_models import init_chat_model

provider = "openai"                        # template base da OpenAI
model    = "ggml-org/gemma-4-E2B-it-GGUF"  # nome do modelo
config   = provider + ":" + model

params = {
    "model": config,
    "api_key": "",
    "temperature": 0.3,
    "max_tokens": 1500,
    # "extra_body": {"repeat_penalty": 1.15, "min_p": 0.05},
    "reasoning": {"effort": "low", "summary": "auto"},
    "base_url": "http://127.0.0.1:8080/v1",  # API endpoint
}

llm = init_chat_model(**params)
response = llm.invoke("escreva um poema")
